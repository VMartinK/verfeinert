# Verfeinert v0.4.0 Architecture Closure Report

Date: 2026-08-21

Scope: final architecture and dependency audit for the v0.4.0 local release
candidate. This report covers package code, workflow orchestration, public
examples, and release-required full-lite reproduction paths after CP15.

Status: PASS. No release-blocking architecture violation was found.

boundary tests:

The package-code scans above returned no forbidden runtime imports after the
cleanup recorded below. Broad text scans returned expected documentation,
configuration, and example labels, not framework branches.

## Boundary Cleanup

Two import-boundary issues were corrected during the audit:

- `workflow.visualization` now imports `cost_value` and `metric_value` from the
  public `verfeinert.ansatz_analyzer` surface instead of reaching into
  `ansatz_analyzer.collections`.
- `workflow.config` now imports `GeneratorValidationError` from the public
  `verfeinert.ansatz_generator` surface instead of the generator validation
  submodule.

This is additive public API cleanup only. It does not change scientific
semantics, schemas, metric computations, visualization output, evolution
selection, or workflow stage behavior.

## Explicit Search Findings

Generator:

- No runtime PennyLane import was found.
- No workflow-added backend dependency was found.
- The callable-source exporter still contains literal source strings such as
  `import pennylane as qml`; these are emitted into generated user code only and
  do not make the generator a scientific runtime backend.

Evolver:

- No pandas/DataFrame imports.
- No analyzer imports.
- No PennyLane/QNode imports.
- No Matplotlib/visualization imports.
- No CX01/MIXT5G campaign-name branches.

Workflow:

- No notebook, legacy package, or thesis-processing import.
- No analyzer metric/materialization/private pipeline import.
- No generator operation/compiler/private validation import after cleanup.
- `campaign_type` is a generic workflow enum, not a campaign-name branch.

Visualization:

- No analyzer metric execution or materialization import.
- Prepared visualization data is derived from persisted values and refs.
- Global and campaign terminology is visualization-domain vocabulary, not
  campaign-name conditionals.

Examples:

- Example scripts use public package APIs and caller-owned output roots.
- Declarative full-lite configs do not require wrapper Python.
- Example notebooks have null execution counts and no stored outputs; they are
  optional interfaces over example scripts and not package/runtime dependencies.

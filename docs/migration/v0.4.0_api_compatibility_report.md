# Verfeinert v0.4.0 Public API Compatibility Report

Date: 2026-08-21

Baseline: v0.3.2 merge commit
`34004fb70514158394f3f93f3e1c74fe9596c616`.

Status: PASS. No public import removals, canonical schema changes, or
representative v0.3.2 usage regressions were found.

## Audit Scope

The compatibility audit covered:

- top-level package version/import surface;
- public `__all__` exports in `core`, `ansatz_generator`, `ansatz_analyzer`,
  `ansatz_evolver`, `workflow`, and analyzer visualization;
- representative v0.3.2 usage of generator, analyzer, evolver, WorkflowRunner,
  and visualization model APIs;
- canonical schema files under `schemas/` and packaged schema resources;
- package version metadata, which intentionally remains `0.3.2` until CP19.

## Representative Usage Tests

New compatibility coverage:

```bash
pytest tests/test_v040_api_compatibility.py -q
```

Result:


The test exercises:

- generator: `build_sanz19_candidate_record` plus `export_candidate_json`;
- analyzer: `AnalyzerConfig`, `StructuralCostConfig`, and
  `AnalysisPipeline(...).run(...)` over structural-cost analysis;
- evolver: positional `CandidateRef(...)` and `EvolutionRunState(...)`
  constructor usage;
- workflow: legacy/minimal `WorkflowConfig.from_mapping` plus
  `WorkflowRunner(...).run()` for an individual workflow;
- visualization: positional `ObjectivePoint` and `ObjectiveSeries`
  constructor usage.

These tests are intentionally representative rather than exhaustive; the
existing test suite continues to cover the broader public API.

## Compatibility Findings

- Existing public imports remain available.
- Existing positional constructor patterns tested above remain valid.
- Legacy workflow mappings with top-level `run_id` and `output_root` still
  normalize through `WorkflowConfig.from_mapping`.
- Existing visualization semantic model positional arguments remain valid;
  newer fields such as `score` remain keyword-only additions.
- No canonical artifact meaning was changed.
- No public scientific defaults were silently reinterpreted.

## Versioning Note

```text

```

This is expected. CP19 owns the coordinated version bump to `0.4.0` across
`pyproject.toml`, runtime version metadata, `CITATION.cff`, changelog, and other
authoritative references.

## Blocker Review

No CP18 blocker was triggered:

- no public import was removed;
- no tested representative v0.3.2 usage broke;
- no canonical schema change was required;
- no public constructor argument order tested here was reordered;
- no documented compatibility normalization was removed.

The public API is compatible enough to proceed to CP19 versioning, subject to
the final full-suite and release-candidate validation gates.
